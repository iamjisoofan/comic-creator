# 儿童漫画创作系统 — 设计文档

日期：2026-08-10（2026-08-10 修订：出图方案由 Draw Things 改为 Claude 直接生成 SVG）
状态：已确认，待实施

---

## 1. 这是什么

一个让 9 岁小朋友当"作者"的漫画创作系统。他提供角色和故事想法，系统把它变成一本 Dog Man 风格的彩色漫画书，可以在浏览器里读。

**核心目标不是产出漫画，是让他体验"我创作了一本书"。** 因此系统必须让他拥有自己的角色库和连载历史——这些数据属于他，跨书累积。

**第二目标：他想照着画在纸上时画得出来。** 这条不是附加需求，它是画风的硬约束——见 [`comic.md`](../../../comic.md)。

## 2. 关键决策与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| **出图方案** | **Claude 直接生成 SVG** | Dog Man 造型就是几个圆和方块，SVG 完全画得了；换成写实漫画则不可行 |
| 角色一致性 | SVG `<symbol>` 复用 | 不是"长得像"，是同一段代码——一致性问题被删除而非解决 |
| 画风 | 固定 Dog Man 风格，规范见 `comic.md` | 系统的视觉身份；9 岁说不清"画风"但说得清"要好笑的" |
| 复杂度控制 | 硬性图形预算（角色 ≤12 图形，每格 ≤20） | 防止画得太精致导致孩子临摹不了 |
| 手绘歪扭感 | **不模拟** | 需要滤镜，而滤镜是禁止项；刻意做旧只增加复杂度，几何简洁本身已够孩子气 |
| 文字渲染 | 文字层与图形层分离 | 改台词不用重画；SVG 文本清晰可选中 |
| 流水线 | 先出剧本（可改）再按章作画 | 把便宜的决策和昂贵的执行分开，让作者在最便宜时行使创作权 |
| 入口 | Claude Code skill（家长代为输入） | 9 岁用不了终端；先验证玩法，接口留干净，之后再做网页创作台 |
| 存储 | 纯文件，无服务无数据库 | 大人能随时手动改任何一句台词、任何一个图形 |
| 语言 | 英文 | 用户指定 |
| 成品 | 彩色 | 用户指定 |

### 为什么放弃 Draw Things / Stable Diffusion

原方案是本地跑 SDXL 出图，后被否决。SVG 方案删掉了以下全部复杂度：

- 8GB 模型下载、Draw Things 安装、GPU 占用、16GB 内存压力
- 25 秒/格的等待（150 格约 1 小时）
- 双锚点 + IPAdapter 的角色一致性调参
- 「禁止 SD 画文字」的负向 prompt 对抗
- 四条技术风险中的三条

代价是画面上限较低：**不会惊艳，但也不会崩坏**，永远稳定在"还不错的简笔画"。对本项目而言这是优点——目标本来就是"看起来像他自己能画出来的"。

**渲染层是可插拔的，故事层才是资产。** `script.json` 的结构不依赖渲染方式，将来若要接 SD，剧本和角色设定全部可复用。

## 3. 规模

- 一本书 4–5 章 / 一章 4–5 页 / 一页 4–6 格
- **合计约 64–150 格**

SVG 生成本身很快，但 150 格仍是可观的输出量，因此保留**按章推进**：一章 16–30 格。这同时给了小朋友连载式的阅读节奏。

## 4. 文件结构

系统没有服务、没有数据库、没有需要安装的软件。所有状态都是可直接打开编辑的纯文本。

```
comic.md                      # 绘画规范（运行时契约，每次作画前必读）
comics/
  characters/                 # 角色库 —— 跨书共享，小朋友的资产
    dog-man.md                #   性格、口头禅、关系
    dog-man.svg               #   4 个姿势的 <symbol> 定义
  books/
    01-the-lost-bone/
      book.md                 #   书名 + 大纲 + 每章一句话
      script.json             #   全书分镜
      panels/                 #   ch1-p1-01.svg ... 每格一个文件
      index.html              #   双击即读的成书（自包含）
  history.md                  # 连载记忆：出过哪些书、角色经历了什么
```

设计要点：

- **角色库独立于书**：同一角色能出现在第 1 本和第 5 本。这个目录就是他攒下的家当。
- **每本书自包含**：整个文件夹可拷贝、可删除，没有隐藏状态。
- **`history.md` 是 AI 的长期记忆**：开新书前先读，所以 AI 记得上一本发生了什么。
- **每格一个 `.svg` 文件**：可单独删除重画、可手动编辑、已生成的不重复生成。

## 5. 角色机制

一个角色 = 一个 md（故事设定）+ 一个 svg（视觉定义）。

`characters/dog-man.md`：

```markdown
# 狗狗警长 (Dog Man)

性格：勇敢但笨笨的，容易分心，闻到骨头走不动路
口头禅：「汪！交给我！」
关系：猫咪坏蛋是死对头 / 小机器人是好朋友
经历：第1本学会开警车，第2本怕水
标志物：金色警徽、蓝色制服、棕色垂耳
```

`characters/dog-man.svg`：4 个 `<symbol>`，遵守 `comic.md` 的图形预算（每个 ≤12 图形）。

```xml
<symbol id="dogman-idle"    viewBox="0 0 100 150">...</symbol>
<symbol id="dogman-happy"   viewBox="0 0 100 150">...</symbol>
<symbol id="dogman-shocked" viewBox="0 0 100 150">...</symbol>
<symbol id="dogman-angry"   viewBox="0 0 100 150">...</symbol>
```

**一致性是结构性保证，不是努力的结果。** 第 1 格和第 137 格引用的是同一个 `<symbol>`，像素级相同。这与 SD 方案有本质区别——那边是尽力逼近，这边是不可能不同。

**只做 4 个姿势。** 复杂动作用漫画符号表达（跑 = 站姿 + 速度线，摔倒 = 站姿转 90°）——细则见 `comic.md` 第 5 节。

### 新角色诞生流程

小朋友描述 → AI 追问（名字 / 好人坏人 / 有什么特别）→ 写 md → **先只画 `-idle` 一个姿势给他看**：

> 「这是你的飞天乌龟，像你想的吗？」

像 → 补齐其余 3 个姿势，入库。
不像 → 改，重画。

这一步决定后面 100 格长什么样，值得单独卡一次。这也是最有"作者感"的时刻——他创造的角色从此有了名字和长相，住在他的角色库里。

## 6. 剧本阶段

### 第一步：大纲（给人看）

AI 先读 `history.md` 和 `characters/`，带着记忆开口问三个问题：

1. **角色** —— 列出已有角色让他挑，也可以说要新的
2. **故事** —— 一句话也行（"狗狗的骨头被偷了"）
3. **气氛** —— 搞笑 / 冒险 / 温馨 / 有点吓人（**不问画风**，画风固定）

然后生成 4–5 章骨架，**用大白话讲给小朋友听**（不给他看 JSON），他确认或修改。这是他行使作者权最便宜也最有效的时刻，必须过这一关。

### 第二步：分镜（给机器看）

大纲敲定后展开成 `script.json`。这一步不需要小朋友确认（100 格他看不完），家长可扫一眼。

```json
{
  "title": "The Lost Bone",
  "tone": "funny",
  "characters": ["dog-man", "robo-buddy"],
  "chapters": [
    {
      "number": 1,
      "title": "Where's My Bone?!",
      "pages": [
        {
          "number": 1,
          "layout": "2x2",
          "panels": [
            {
              "id": "ch1-p1-01",
              "shot": "wide",
              "description": "Dog Man sleeping in bed, big bone under the bed, morning sun",
              "characters": [{ "id": "dog-man", "pose": "idle" }],
              "dialogue": [],
              "sfx": "ZZZZZ..."
            },
            {
              "id": "ch1-p1-02",
              "shot": "close-up",
              "description": "Dog Man looking under the bed, empty floor",
              "characters": [{ "id": "dog-man", "pose": "shocked" }],
              "dialogue": [{ "speaker": "dog-man", "text": "MY BONE!!" }],
              "sfx": "GASP!"
            }
          ]
        }
      ]
    }
  ]
}
```

字段规则：

- **`characters` 携带姿势**：`{id, pose}`，pose ∈ `idle` / `happy` / `shocked` / `angry`。作画时直接 `<use href="#dog-man-{pose}">`。
- **`description` 只描述画面**，用于生成背景和道具，**绝不含任何台词文字**。
- **`dialogue` / `sfx` 不进图形层**，由 `index.html` 的文本层叠加。改台词不用重画。
- **`shot` 只有三种**：`wide` / `medium` / `close-up`，对应角色的缩放和裁切。
- **`layout` 用预设值**，覆盖 4–6 格，CSS Grid 实现，不做自由排版：

  | 值 | 格数 | 版式 |
  |---|---|---|
  | `2x2` | 4 | 两行两列 |
  | `1-2-1` | 4 | 通栏 / 两格 / 通栏 |
  | `1-2-2` | 5 | 通栏 / 两格 / 两格 |
  | `2-1-2` | 5 | 两格 / 通栏 / 两格 |
  | `2x3` | 6 | 三行两列 |
  | `3x2` | 6 | 两行三列 |

- **`id` 即文件名**：`ch1-p1-02` → `panels/ch1-p1-02.svg`。

### 修改入口

- **作画前**：改大纲 → 重新展开分镜。适合"不喜欢这个结局"。
- **作画后**：直接改 `script.json` 台词 → 刷新网页。零成本，字不在图形里。
- **单格不满意**：删掉那个 `.svg` → 重跑该章，只重画缺失的格。

## 7. 作画阶段

### 一格 SVG 长什么样

因为角色是复用的 `<symbol>`，每格只需要背景 + 引用 + 少量道具，非常短：

```xml
<svg viewBox="0 0 400 300">
  <rect width="400" height="300" fill="#FFFFFF"/>
  <line x1="0" y1="240" x2="400" y2="240" stroke="#000" stroke-width="6"/>
  <use href="#dog-man-shocked" x="150" y="90" width="100" height="150"/>
  <rect x="60" y="200" width="50" height="20" rx="10"
        fill="#F5D9B0" stroke="#000" stroke-width="6"/>
</svg>
```

**规则全部来自 [`comic.md`](../../../comic.md)**——图形预算、调色板、线条粗细、禁止清单。本设计文档不重复那些内容，`comic.md` 是唯一来源。

### 增量作画

作画前检查目标 `.svg` 是否存在，存在则跳过。理由不再是省时间（SVG 生成很快），而是：

- **保护已确认的内容** —— 小朋友说"这格我喜欢"，就不该被后续操作覆盖
- **保护手动修改** —— 你手改过的 SVG 不会被冲掉
- **单格重画** —— 删一个文件重跑即可
- **按章推进天然实现** —— 就是"只有这章的文件不存在"

## 8. 成书 `index.html`

一个静态 HTML 文件，双击打开，不需要任何服务。

- **角色定义**：所有用到的角色 `<symbol>` 内联进页面顶部的 `<defs>`
- **分格**：CSS Grid 按 `layout` 排版，每格内联对应的 panel SVG
- **气泡**：SVG 覆盖在画面上层，白底黑框 + 三角尾巴指向说话者
- **拟声词**：黄底黑边粗体大字，随机 ±15° 旋转
- **翻页**：向下滚动或左右键

> **必须绕开的坑**：`index.html` **不能**用 `fetch()` 读 `script.json` 或 `.svg` 文件——`file://` 下 fetch 本地文件被 CORS 拦截，页面会一片空白。生成 HTML 时**把所有数据和 SVG 内联进去**。

结果：`books/01-the-lost-bone/index.html` **单文件即可分享**——发给爷爷奶奶一个文件就行，不用整个文件夹。这是 SVG 方案相对 SD 方案的额外收获（那边图片是外部 png，必须整包拷贝）。

## 9. 命令

| 命令 | 做什么 |
|---|---|
| `/comic new` | 读记忆 → 问三问 → 出大纲 → 讲给小朋友 → 确认后展开 `script.json` |
| `/comic character` | 造新角色：追问 → 画 idle 姿势确认 → 补齐 4 姿势入库 |
| `/comic draw [章号]` | 画指定章（省略则画下一个未完成的章），跳过已存在的格 |
| `/comic read` | 打开 `index.html` |

典型流程：`new`（他参与出大纲）→ `draw 1` → `read`（他读第 1 章）→ `draw 2` → …… 分几天读完，即为连载。

## 10. 失败处理

| 情况 | 处理 |
|---|---|
| 某格画得不对 | 删掉该 `.svg`，重跑该章 |
| 角色画得不像 | 重画 `characters/xxx.svg`，删掉含该角色的格，重跑 |
| 故事不满意 | 作画前改大纲；作画后改 `script.json` 台词（不重画图形） |
| 画得太复杂 | 改 `comic.md` 收紧预算，删图重画 |

## 11. 第一版不做（YAGNI）

- ❌ 网页创作台（让小朋友自己操作）—— 等确认玩法他真的喜欢再做
- ❌ Stable Diffusion / Draw Things 渲染层 —— 接口留干净，将来想要时再接
- ❌ 动画、交互效果
- ❌ 手绘质感模拟（滤镜）—— 见第 2 节决策表
- ❌ 自由分格排版 —— 只用预设 layout
- ❌ 中文 / 多语言 —— 只做英文
- ❌ PDF / 打印导出 —— 浏览器 Ctrl+P 即可
- ❌ 自动追踪角色成长 —— 完本时 AI 往 `history.md` 追加一段即可

## 12. 验收标准

1. `/comic character` 造出新角色 → `characters/` 下 md 和 svg 都在，svg 含 4 个 `<symbol>`，每个 ≤12 图形
2. `/comic new` 产出 `script.json` → 章/页/格数在范围内，`description` 中不含任何台词文字
3. `/comic draw 1` 画出第 1 章全部格 → 每格 ≤20 图形，只用调色板颜色，无渐变/阴影/曲线路径
4. 再次 `/comic draw 1` → 全部跳过（增量作画生效）
5. 双击 `index.html` → `file://` 下不空白，气泡文字清晰可读，分格正确，同一角色跨格完全一致
6. **打印一格给小朋友，让他照着画 —— 2 分钟内画得完**

第 6 条是总闸。画不完说明画复杂了，收紧 `comic.md` 重来。

## 13. 已知风险

| 风险 | 应对 |
|---|---|
| SVG 简笔画对 9 岁小孩吸引力不足 | 先做完整一章给他看，观察反应。这是**唯一真正的产品风险**，其余都是技术细节 |
| 复杂剧情用 4 姿势 + 符号表达不出来 | 剧本阶段就约束：AI 写分镜时只能用能表达的动作。表达不了就改剧情 |
| 我画得过于精致导致临摹不了 | `comic.md` 的硬性预算 + 验收标准第 6 条 |
