# 儿童漫画创作系统 — 设计文档

日期：2026-08-10
状态：已确认，待实施

修订记录：
- v1 出图用本地 Draw Things (Stable Diffusion)
- v2 改为 Claude 直接生成 SVG
- **v3（当前）改为 Claude 生成结构化 JSON，由渲染器转成 SVG**

---

## 1. 这是什么

一个让 9 岁小朋友当"作者"的漫画创作系统。他提供角色和故事想法，系统把它变成一本 Dog Man 风格的彩色漫画书，可以在浏览器里读。

**核心目标不是产出漫画，是让他体验"我创作了一本书"。** 因此系统必须让他拥有自己的角色库和连载历史——这些数据属于他，跨书累积。

**第二目标：他想照着画在纸上时画得出来。** 这条不是附加需求，它是画风的硬约束——见 [`comic.md`](../../../comic.md)。

## 2. 关键决策与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| **画面格式** | **Claude 产出结构化 JSON，代码渲染成 SVG** | 让违反画风变成**不可表达**，而不是"事后检测" |
| 角色一致性 | 角色定义复用，同一份 shapes | 不是"长得像"，是同一份数据——一致性问题被删除而非解决 |
| 画风 | 固定 Dog Man，规范见 `comic.md` | 系统的视觉身份；9 岁说不清"画风"但说得清"要好笑的" |
| 复杂度控制 | schema 强制图形预算 + `comic.md` 管判断 | 机器能查的交给机器，只留品味给人 |
| 手绘歪扭感 | **不模拟** | 需要滤镜，会增加复杂度，也让孩子更难临摹 |
| 文字渲染 | 文字层与图形层分离 | 改台词不用重画画面 |
| 流水线 | 先出剧本（可改）再按章作画 | 把便宜的决策和昂贵的执行分开 |
| 入口 | Claude Code skill（家长代为输入） | 9 岁用不了终端；先验证玩法，之后再做网页创作台 |
| 存储 | 纯文件，无服务无数据库 | 大人能随时手动改任何一句台词、任何一个图形 |
| 语言 | 英文 | 用户指定 |
| 成品 | 彩色 | 用户指定 |

### 为什么产出 JSON 而不是 SVG

如果 Claude 直接手写 SVG，`comic.md` 的约束只能靠"事后 lint"来保障——而 Claude 画到第 100 格时松懈的概率不低，检测到了还得重画。

改为产出结构化 JSON 后，约束从**规则**变成**物理定律**：

| 约束 | 手写 SVG | 结构化 JSON |
|---|---|---|
| 禁止渐变 | 靠自觉 + lint | `t` 只有 6 个合法值，没有 gradient |
| 颜色必须在调色板内 | 靠自觉 + lint | `fill` 只接受颜色**名字**，不接受色值 |
| 线条粗细统一 | 靠自觉 + lint | 渲染器统一施加，Claude 碰不到 |
| 图形数量超限 | lint 检测 | schema 直接拒绝 |
| 画面里混入文字 | lint 检测 | 没有 text 类型 |

副作用收益：Claude 每格输出量减半；家长和小朋友直接看懂并修改（改 `"fill": "red"` 比改 SVG 属性容易得多）。

### 为什么放弃 Stable Diffusion（v1 方案）

原方案是本地跑 SDXL 出图，已否决。删掉的复杂度：8GB 模型下载、Draw Things 安装、GPU 占用、16GB 内存压力、25 秒/格的等待、IPAdapter 一致性调参、「禁止 SD 画文字」的负向 prompt 对抗。

代价是画面上限较低：**不会惊艳，但也不会崩坏**。对本项目是优点——目标本来就是"看起来像他自己能画出来的"。

**渲染层可插拔，故事层才是资产。** `script.json` 不依赖渲染方式，将来若要接 SD，剧本和角色设定全部可复用。

## 3. 技术栈

| 层 | 选择 | 说明 |
|---|---|---|
| 语言 | **TypeScript** | 渲染器与 schema 将来要被网页创作台复用 |
| 运行时 | **Node.js 22 LTS+** | |
| 执行 | **tsx** | 直接跑 TS，无编译步骤 |
| 测试 | **Vitest** | 原生支持 TS，零配置 |
| Schema | **Zod** | Claude 生成的 JSON 必须在入口校验 |
| 阅读器输出 | 静态 HTML + CSS Grid + 约 20 行原生 JS | 单文件、`file://` 可开、可直接分享 |

依赖四个：`tsx`、`vitest`、`typescript`（开发），`zod`（运行时）。

`typescript` 不是可选的：`tsx` 只负责**运行** TS，不做类型检查；`tsc --noEmit` 才是真正的类型验证，而选 TypeScript 的全部理由就是类型安全。因此 `package.json` 必须提供 `"typecheck": "tsc --noEmit"` 脚本，并把它当作提交前的验证步骤之一。

**核心分层：**

```
characters/*.json ─┐
                   ├─→ renderPanelSvg()  ─→ SVG   ← 将来浏览器里也用这个函数
panels/*.json    ──┘                        │
script.json      ───────────────────────────┴─→ buildHtml() ─→ index.html
```

`renderPanelSvg()` 是系统枢纽，也是唯一必须共享给未来前端的东西。v1 是 CLI 的一部分，将来原样搬进 React 应用——**这是选 TypeScript 的唯一理由**。

## 4. 规模

- 一本书 4–5 章 / 一章 4–5 页 / 一页 4–6 格
- **合计约 64–150 格**

保留**按章推进**：一章 16–30 格。这同时给了小朋友连载式的阅读节奏。

## 5. 文件结构

```
comic.md                      # 绘画规范（运行时契约，作画前必读）
src/
  schema.ts                   # Zod 定义 —— shape / character / panel / script
  render.ts                   # renderPanelSvg()：JSON → SVG 字符串
  build.ts                    # buildHtml()：组装整本书
  layout.ts                   # 6 种版式 → CSS Grid
  cli.ts                      # 命令行入口
comics/
  characters/                 # 角色库 —— 跨书共享，小朋友的资产
    dog-man.md                #   性格、口头禅、关系
    dog-man.json              #   4 个姿势的 shapes
  books/
    01-the-lost-bone/
      book.md                 #   书名 + 大纲
      script.json             #   全书剧本（意图）
      panels/                 #   ch1-p1-01.json ... 每格画面（实现）
      index.html              #   生成物，双击即读
  history.md                  # 连载记忆
```

要点：

- **角色库独立于书** —— 同一角色能出现在第 1 本和第 5 本。这个目录就是他攒下的家当。
- **剧本与画面分离** —— `script.json` 是**意图**（谁在场、说什么、什么气氛），`panels/*.json` 是**实现**（图形怎么摆）。改台词不碰画面，改画面不碰剧本。
- **每格一个文件** —— 可单独删除重画、可手动编辑、已存在的不重复生成。
- **`index.html` 是生成物** —— 可随时重建，不是需要保护的资产。

## 6. 角色机制

一个角色 = 一个 md（故事设定）+ 一个 json（视觉定义）。

`characters/dog-man.md`：

```markdown
# 狗狗警长 (Dog Man)

性格：勇敢但笨笨的，容易分心，闻到骨头走不动路
口头禅：「汪！交给我！」
关系：猫咪坏蛋是死对头 / 小机器人是好朋友
经历：第1本学会开警车，第2本怕水
标志物：金色警徽、蓝色制服、棕色垂耳
```

`characters/dog-man.json`：

```json
{
  "id": "dog-man",
  "name": "Dog Man",
  "viewBox": [0, 0, 100, 150],
  "poses": {
    "idle":    [ { "t": "circle", "cx": 50, "cy": 35, "r": 28, "fill": "beige" } ],
    "happy":   [ ... ],
    "shocked": [ ... ],
    "angry":   [ ... ]
  }
}
```

每个姿势 ≤12 个图形（schema 强制）。

**一致性是结构性保证。** 第 1 格和第 137 格用的是同一份 `poses.idle` 数据，渲染出来完全相同。这与 SD 方案有本质区别——那边是尽力逼近，这边是不可能不同。

**只做 4 个姿势**，复杂动作用漫画符号表达——细则见 `comic.md` 第 4 节。

### 新角色诞生流程

小朋友描述 → AI 追问（名字 / 好人坏人 / 有什么特别）→ 写 md → **先只画 `idle` 一个姿势渲染给他看**：

> 「这是你的飞天乌龟，像你想的吗？」

像 → 补齐其余 3 个姿势，入库。不像 → 改，重画。

这一步决定后面 100 格长什么样，值得单独卡一次。也是最有"作者感"的时刻——他创造的角色从此有了名字和长相，住在他的角色库里。

## 7. 剧本阶段

### 第一步：大纲（给人看）

AI 先读 `history.md` 和 `characters/`，带着记忆开口问三个问题：

1. **角色** —— 列出已有角色让他挑，也可以说要新的
2. **故事** —— 一句话也行（"狗狗的骨头被偷了"）
3. **气氛** —— 搞笑 / 冒险 / 温馨 / 有点吓人（**不问画风**）

然后生成 4–5 章骨架，**用大白话讲给小朋友听**（不给他看 JSON），他确认或修改。这是他行使作者权最便宜也最有效的时刻，必须过这一关。

### 第二步：分镜

大纲敲定后展开成 `script.json`。这一步不需要小朋友确认（100 格他看不完），家长可扫一眼。

```json
{
  "title": "The Lost Bone",
  "tone": "funny",
  "chapters": [
    {
      "number": 1,
      "title": "Where's My Bone?!",
      "pages": [
        {
          "number": 1,
          "layout": "2x2",
          "panels": [
            {
              "id": "ch1-p1-01",
              "shot": "wide",
              "description": "Dog Man sleeping in bed, big bone under the bed",
              "cast": ["dog-man"],
              "dialogue": [],
              "sfx": "ZZZZZ..."
            },
            {
              "id": "ch1-p1-02",
              "shot": "close-up",
              "description": "Dog Man looking under the bed, empty floor",
              "cast": ["dog-man"],
              "dialogue": [{ "speaker": "dog-man", "text": "MY BONE!!" }],
              "sfx": "GASP!"
            }
          ]
        }
      ]
    }
  ]
}
```

字段规则：

- **`cast` 只列角色 ID**，不含姿势和位置——那些属于画面实现，在 `panels/*.json` 里。
- **`description` 只描述画面**，供作画阶段参考，**绝不含台词文字**。
- **`dialogue` / `sfx` 不进图形层**，由渲染器叠加。改台词不用重画。
- **`shot`** ∈ `wide` / `medium` / `close-up`。
- **`id` 即文件名**：`ch1-p1-02` → `panels/ch1-p1-02.json`。
- **`layout`** 用预设值，覆盖 4–6 格：

  | 值 | 格数 | 版式 |
  |---|---|---|
  | `2x2` | 4 | 两行两列 |
  | `1-2-1` | 4 | 通栏 / 两格 / 通栏 |
  | `1-2-2` | 5 | 通栏 / 两格 / 两格 |
  | `2-1-2` | 5 | 两格 / 通栏 / 两格 |
  | `2x3` | 6 | 三行两列 |
  | `3x2` | 6 | 两行三列 |

### 修改入口

- **作画前**：改大纲 → 重新展开分镜。适合"不喜欢这个结局"。
- **作画后**：改 `script.json` 台词 → 重建。零成本，字不在图形里。
- **单格不满意**：删掉那个 `panels/*.json` → 重跑该章，只重画缺失的格。

## 8. 作画阶段

Claude 为每一格产出一个 JSON 文件。画布 `400 × 300`。

```json
{
  "id": "ch1-p1-02",
  "shapes": [
    { "t": "line", "x1": 0, "y1": 240, "x2": 400, "y2": 240 },
    { "t": "rect", "x": 60, "y": 200, "w": 50, "h": 20, "r": 10, "fill": "beige" }
  ],
  "cast": [
    { "id": "dog-man", "pose": "shocked", "x": 150, "y": 60, "scale": 1.2 }
  ]
}
```

- `shapes` —— 背景和道具，≤20 个
- `cast` —— 角色摆放，≤3 个；`pose` 在这里决定（属于画面实现）

**规则全部来自 [`comic.md`](../../../comic.md)** 和 `src/schema.ts`。本文档不重复。

### 增量作画

作画前检查目标 `.json` 是否存在，存在则跳过。理由不是省时间，而是：

- **保护已确认的内容** —— 小朋友说"这格我喜欢"，不该被后续操作覆盖
- **保护手动修改** —— 手改过的文件不会被冲掉
- **单格重画** —— 删一个文件重跑即可
- **按章推进天然实现** —— 就是"只有这章的文件不存在"

## 9. 渲染与成书

### `renderPanelSvg()`

输入一个 panel JSON + 用到的角色定义，输出 SVG 字符串。职责：

- 把 shape 词表转成 SVG 元素
- **统一施加描边**：`stroke="#000000" stroke-width="6" stroke-linecap="round" stroke-linejoin="round"`
- **把颜色名解析成色值**（`beige` → `#F5D9B0`）
- 把 `cast` 里的角色姿势按 `x/y/scale` 摆进画面

Claude 碰不到描边和色值，所以不可能画错。

### `buildHtml()`

- **分格**：CSS Grid 按 `layout` 排版，每格内联渲染好的 SVG
- **气泡**：HTML 绝对定位覆盖在 SVG 上层，白底黑框 + CSS 三角尾巴。用 HTML 而非 SVG 文本，因为需要自动换行
- **拟声词**：黄底黑边粗体大字，随机 ±15° 旋转
- **翻页**：向下滚动或左右键（约 20 行原生 JS）

> **必须绕开的坑**：`index.html` **不能**用 `fetch()` 读本地 JSON——`file://` 下会被 CORS 拦截，页面一片空白。**所有数据和 SVG 必须内联进 HTML**。

结果：**单个 HTML 文件即可分享**，发给爷爷奶奶发一个文件就行。

## 10. 命令

| 命令 | 做什么 |
|---|---|
| `/comic new` | 读记忆 → 问三问 → 出大纲 → 讲给小朋友 → 确认后展开 `script.json` |
| `/comic character` | 造新角色：追问 → 画 idle 渲染确认 → 补齐 4 姿势入库 |
| `/comic draw [章号]` | 为该章缺失的格产出 panel JSON，然后重建 `index.html` |
| `/comic read` | 打开 `index.html` |

底层 CLI（skill 调用，人也能直接用）：

```
npx tsx src/cli.ts build <book-dir>      # 重建 index.html
npx tsx src/cli.ts check <path>          # 校验 JSON 是否合法
```

典型流程：`new`（他参与出大纲）→ `draw 1` → `read`（他读第 1 章）→ `draw 2` → …… 分几天读完，即为连载。

## 11. 失败处理

| 情况 | 处理 |
|---|---|
| JSON 不合 schema | `check` 报出具体路径和原因，改了重跑 |
| 某格画得不对 | 删掉该 `panels/*.json`，重跑该章 |
| 角色画得不像 | 重画 `characters/xxx.json`，`build` 后全书自动更新（角色是引用，不是拷贝） |
| 故事不满意 | 作画前改大纲；作画后改 `script.json` 台词后 `build` |
| 画得太复杂 | 改 `comic.md` 收紧，删图重画 |

注意第三行：**改角色定义会自动传播到全书所有格**，因为角色是渲染时引用的，不是烘焙进每一格的。这是 JSON 方案相对手写 SVG 的额外收获。

## 12. 第一版不做（YAGNI）

- ❌ 网页创作台（方案①）—— 等确认玩法他真的喜欢再做
- ❌ Stable Diffusion 渲染层 —— 接口留干净，将来想要时再接
- ❌ 动画、交互效果
- ❌ 手绘质感模拟
- ❌ 自由分格排版 —— 只用 6 种预设
- ❌ 中文 / 多语言 —— 只做英文
- ❌ PDF / 打印导出 —— 浏览器 Ctrl+P 即可
- ❌ 自动追踪角色成长 —— 完本时 AI 往 `history.md` 追加一段即可

## 13. 验收标准

1. `check` 能拒绝一个超预算（13 图形）的角色姿势，并指出是哪个姿势
2. `check` 能拒绝一个用了非法颜色（`"fill": "#FF0000"`）的 panel
3. `/comic character` 造出新角色 → md + json 都在，4 个姿势齐全，渲染出来能看出是什么动物
4. `/comic new` 产出合法 `script.json` → 章/页/格数在范围内，`description` 不含台词
5. `/comic draw 1` 产出第 1 章全部 panel JSON 并重建 HTML
6. 再次 `/comic draw 1` → 全部跳过（增量作画生效）
7. 双击 `index.html` → `file://` 下不空白，气泡文字清晰，分格正确，同一角色跨格完全一致
8. **打印一格给小朋友，让他照着画 —— 2 分钟内画得完**

第 8 条是总闸。画不完说明画复杂了，收紧 `comic.md` 重来。

## 14. 已知风险

| 风险 | 应对 |
|---|---|
| 简笔画对 9 岁小孩吸引力不足 | 先做完整一章给他看。这是**唯一真正的产品风险**，其余都是技术细节 |
| 用 6 种图形 + 4 姿势表达不出剧情 | 剧本阶段就约束：只写画得出来的动作。表达不了就改剧情 |
| Claude 画得过于精致导致临摹不了 | schema 管数量，`comic.md` 管判断，验收第 8 条兜底 |
